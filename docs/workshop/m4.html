ฐานข้อมูลต่อติด

~45 นาที

เป้าหมาย: Supabase พร้อมใช้ ทั้ง schema, RLS, auth และ env ครบทั้งฝั่ง local และ Vercel

1. สร้างโปรเจกต์ Supabase

ที่ supabase.com/dashboard → New project (region Singapore) โปรเจกต์ใช้เวลาตั้งตัวราว 2 นาที ระหว่างรออ่านขั้นถัดไปได้ จากนั้นจด Project URL กับ key ฝั่ง public (dashboard รุ่นใหม่: Project Settings → API Keys ใช้ publishable key ขึ้นต้น sb_publishable_ · รุ่นเก่า: Settings → API ใช้ anon key ขึ้นต้น eyJ สองแบบนี้ใช้แทนกันได้)

2. แปลง schema ที่อนุมัติไว้ให้เป็น SQL (คนอ่านก่อนรัน)

พูดกับ agent (agy)

ทำเฟส M4 ตาม docs/PLAN.md: เขียน SQL migration จาก schema ที่อนุมัติไว้: ครบทั้งตาราง, enum สถานะ, ความสัมพันธ์ และเปิด RLS ทุกตาราง โดยตารางหมวดหมู่ให้อ่านแบบ public ได้ (เขียนเฉพาะผู้ล็อกอิน) ส่วนตารางอื่นทั้งอ่านและเขียนเฉพาะผู้ล็อกอิน ปิดท้าย migration ด้วย seed หมวดหมู่ตัวอย่าง 3 หมวด แสดง SQL ให้อ่านทวนกันก่อน และบันทึกเป็นไฟล์ supabase/migrations/0001_init.sql ไว้ใน repo ด้วย ยังไม่ต้องรันอะไร

อ่าน SQL ที่ได้ด้วยกันทั้งห้อง (จุดสอน: RLS คือเส้นชีวิตของ BaaS ส่วนเหตุที่หมวดหมู่เปิดอ่าน public ได้เพราะข้อมูลไม่ sensitive ทั้งยังทำให้หน้า /test พิสูจน์การเชื่อมต่อได้ตั้งแต่ยังไม่มีระบบล็อกอิน ถ้าปิดหมด RLS จะบล็อกแบบเงียบจนดูเหมือนต่อไม่ติด) แล้วค่อยวางรันใน SQL Editor ของ Supabase

3. เปิด Passwordless Auth

Authentication → Sign In / Up → เปิด Email (magic link/OTP) แล้วเพิ่มอีเมลตัวเองเป็น user แรกในแท็บ Users

(แนะนำ) ต่อ Resend เป็น custom SMTP เพื่อปลดล็อกเพดานอีเมล built-in (2 ฉบับ/ชม.): Project Settings → Auth → SMTP Settings ใส่ host smtp.resend.com · port 465 · user resend · password ใส่ API key ที่สร้างไว้ตามหน้า Prerequisites

4. ต่อสาย env และ client

npm install @supabase/supabase-js @supabase/ssr

สร้าง .env.local (และ .env.example ที่ไม่มีค่าจริงไว้ commit):

NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_...

พูดกับ agent (agy)

ต่อเฟส M4: สร้าง Supabase client helpers ตามแพตเทิร์น @supabase/ssr (client / server / middleware) วางไฟล์ตาม Directory Architecture ใน docs/PLAN.md โดยใช้ env สองตัวชื่อ NEXT_PUBLIC_SUPABASE_URL และ NEXT_PUBLIC_SUPABASE_ANON_KEY ตามที่มีใน .env.local ห้ามตั้งชื่ออื่น แล้วทำหน้า /test ที่ดึงจำนวนแถวจากตารางหมวดหมู่มาแสดง เสร็จแล้ว commit แบบ conventional

สุดท้าย ใส่ env สองตัวเดียวกันใน Vercel → Settings → Environment Variables จากนั้นให้ agent commit งานทั้งหมด แล้ว git push (การ push จะสั่ง Vercel rebuild ให้ env ใหม่มีผลพอดี)

ห้าม commit .env.local เด็ดขาด create-next-app ใส่ .gitignore กันไว้ให้แล้ว แต่ตรวจซ้ำด้วย git status ก่อน commit เสมอ
