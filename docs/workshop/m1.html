เป้าหมาย: โครง Next.js รันได้ + brainstorm ระบบกับ AI จนได้แผนที่อนุมัติแล้ว + บันทึกลง repo เพราะ AGENTS.md และ PLAN.md ที่ได้จะเป็นรากของการ handoff ทั้งวัน

1. Scaffold โปรเจกต์

npx create-next-app@latest tdc-e-asset

คำถามตอนสร้างอาจต่างกันเล็กน้อยตามเวอร์ชัน หลักที่ต้องได้คือ: TypeScript ✓ · Tailwind ✓ · App Router ✓ · src/ ✓ ที่เหลือตอบค่า default (linter เลือก ESLint) จากนั้นติดตั้ง shadcn/ui (ตอบค่า default):

cd tdc-e-asset && npx shadcn@latest init
git add -A && git commit -m "chore: init shadcn/ui"

เปิดเทอร์มินัลแท็บที่สอง (cd เข้าโปรเจกต์) สำหรับ dev server แล้วปล่อยรันค้างไว้ทั้งวัน ส่วนงาน agent และ git ทั้งหมดทำในแท็บแรก:

npm run dev

2. Brainstorm ระบบกับ AI ก่อนเขียนโค้ดแม้แต่บรรทัดเดียว

เปิด agy แล้วส่ง prompt นี้ทั้งก้อน สังเกตโครงของมันดู: บทบาท → บริบทธุรกิจ → ข้อจำกัด → stack → ฟีเจอร์ → คำสั่งที่ห้ามเขียนโค้ด + คำถามขออนุมัติ นี่คือแพตเทิร์นการเปิดงานกับ AI ที่เอาไปใช้กับโปรเจกต์จริงได้เลย:

พูดกับ agent (agy) · prompt เปิดโปรเจกต์

[บทบาท] สวมบทบาท Senior Full-Stack Architect ผู้เชี่ยวชาญ Next.js (App Router) และ Supabase ใช้พลัง Brainstorming & System Design ช่วยผมวางรากฐาน MVP ของระบบ "TDC e-Asset" [บริบทธุรกิจ] TDC e-Asset คือระบบบริหารจัดการครุภัณฑ์ภายในหน่วยงาน ใช้ติดตามฮาร์ดแวร์ไอทีแบบรวมศูนย์ เช่น คอมพิวเตอร์ตั้งโต๊ะ โน้ตบุ๊ก จอภาพ อุปกรณ์ต่อพ่วง และเซิร์ฟเวอร์ พร้อมประวัติยืม-คืนย้อนหลัง ข้อจำกัด: ทั้งระบบต้องรันบน Free tier เท่านั้น (Vercel Hobby + Supabase Free) และต้องเสร็จเป็น MVP ในหนึ่งวัน [Tech Stack (ห้ามเปลี่ยน)] - Next.js (App Router, TypeScript) + Tailwind CSS + shadcn/ui - Data layer ใช้ Server Actions เท่านั้น ห้ามสร้าง API route สำหรับ CRUD (ยกเว้น route ที่จำเป็นของ auth callback) - Supabase: PostgreSQL + Auth (Magic Link / Email OTP) + Storage - Deploy บน Vercel (push = Preview, merge main = Production) [ฟีเจอร์ MVP] 1. Auth ไร้รหัสผ่าน + Middleware กันทุกหน้าให้เฉพาะ Admin (หน้า landing เป็น public) 2. Asset CRUD: รหัสครุภัณฑ์ หมวดหมู่ จำนวน สถานะเป็น enum: available / borrowed / maintenance ส่วนรูปภาพเก็บเป็นฟิลด์ URL ไว้ก่อน (ระบบอัปโหลดรูปจริงเป็นเฟส Bonus ไม่อยู่ใน MVP) 3. ยืม-คืน พร้อมตัดสต็อก/คืนสต็อกแบบ race-safe ผ่าน Postgres function + RPC 4. Dashboard สรุป 4 การ์ด: ทั้งหมด / พร้อมใช้ / ถูกยืม / ซ่อมบำรุง + รายการยืมล่าสุด 10 รายการ (ทำหน้าที่เป็นหน้าประวัติของ MVP ส่วนหน้าประวัติเต็มเป็นเฟส Bonus) [งานช่วงระดมสมอง (ห้ามเขียนโค้ดแอปตอนนี้)] 1. Database Schema: ใช้ชื่อตารางหลัก categories, assets, transactions, profiles พร้อมคอลัมน์ data type ความสัมพันธ์ enum ของสถานะ และแนวทาง RLS policy ของทุกตาราง 2. Directory Architecture: โครงสร้าง src/app, components และ server actions 3. แผนลงมือแบ่งเฟสให้ตรง milestone ของ workshop: M4 ฐานข้อมูล/ENV · M5 Auth+Middleware · M6 CRUD · M7 ยืม-คืน · M8 Dashboard และระบุแนวทาง race-safe (Postgres function + RPC) ไว้ในเฟส M7 ด้วย วิเคราะห์ให้รอบคอบ ชี้ความเสี่ยงที่เห็น แล้วปิดท้ายด้วยคำถามว่า "อนุมัติ schema และสถาปัตยกรรมนี้หรือไม่ ก่อนบันทึกแผนลง repo"

อ่านแผนที่ได้ ถกกับ agent จนพอใจ (ไม่เห็นด้วยตรงไหนเถียงได้เลย นี่แหละ brainstorming) แล้วค่อยอนุมัติ ให้เวลาอ่านและถกไม่เกิน 10 นาที เป้าคือเช็กว่า schema มีตารางครบตามฟีเจอร์และ RLS ครบทุกตาราง ไม่ใช่ทำแผนให้สมบูรณ์แบบ (ปรับทีหลังได้เสมอเพราะแผนอยู่ใน repo)

3. อนุมัติแล้วให้บันทึกแผนลง repo ไม่ใช่ทิ้งไว้ในแชต

พูดกับ agent (agy) · หลังอนุมัติ

อนุมัติแล้ว ให้บันทึกแผนลง repo: (1) สร้าง AGENTS.md เป็นสัญญากลางสำหรับ AI agent ทุกตัว: สรุประบบ, tech stack, กติกา (Server Actions เท่านั้น, UI ภาษาไทย, conventional commits, เปิด RLS ทุกตาราง, secret อยู่ใน .env.local), และ section "สถานะปัจจุบัน" ที่ต้องอัปเดตก่อน handoff ทุกครั้ง (2) สร้าง docs/PLAN.md เก็บ schema และแผนเฟส M4-M8 ที่เพิ่งอนุมัติ แล้ว commit ทั้งสองไฟล์แบบ conventional

บทเรียนสำคัญ: แผนที่อยู่ในไฟล์ทำให้ agent "ตัวไหนก็ได้" มารับงานต่อได้ (agy, OpenCode และ Cursor อ่าน AGENTS.md ไฟล์เดียวกันทั้งหมด) ส่วนแผนที่อยู่ในแชตจะตายไปพร้อมแท็บ

ตรวจรับก่อนไปต่อ: เปิด AGENTS.md ดูว่ามีครบ 3 ส่วน: สรุประบบ + stack / กติกา / สถานะปัจจุบัน ขาดส่วนไหนสั่ง agent เติมให้ครบ (ไฟล์นี้คือจุดตั้งต้นของการ handoff ถ้าของไม่ครบวันนี้ agent ตัวถัดไปจะหลงทาง)

สายแผนเสียเงินที่จะใช้ Claude Code ด้วย (เช่นตอน Bonus B3): Claude อ่าน CLAUDE.md จึงต้องทำลิงก์ชี้มาที่ไฟล์เดียวกัน:

ln -s AGENTS.md CLAUDE.md && git add CLAUDE.md && git commit -m "chore: point CLAUDE.md to AGENTS.md"

gh repo create tdc-e-asset --public --source=. --push
