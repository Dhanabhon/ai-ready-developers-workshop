สเปกเครื่องที่แนะนำ

ผู้เข้าร่วมส่วนใหญ่ใช้ laptop ซึ่งใช้ได้เลย — ตรวจสเปกให้ผ่านเกณฑ์นี้ก่อนเริ่มติดตั้ง เพราะเราจะเปิด IDE, เทอร์มินัล, AI agent และเบราว์เซอร์พร้อมกันตลอดวัน

01

เตรียมระบบปฏิบัติการและเทอร์มินัล

Windows

บน Windows เราจะทำงานผ่าน WSL2 (Windows Subsystem for Linux) เพราะเครื่องมือ CLI สาย AI เกือบทั้งหมดออกแบบมาสำหรับ Linux/macOS เป็นหลัก ใช้ Windows 10 (เวอร์ชัน 2004 ขึ้นไป) หรือ Windows 11

1.1 ติดตั้ง WSL2 + Ubuntu

เปิด PowerShell แบบ Run as Administrator แล้วรัน:

wsl --install

คำสั่งเดียวนี้จะติดตั้ง WSL2 พร้อม Ubuntu ให้อัตโนมัติ จากนั้นรีสตาร์ตเครื่อง เปิด Ubuntu ครั้งแรกระบบจะให้ตั้ง username / password ของฝั่ง Linux (จำรหัสนี้ไว้ ใช้กับ sudo)

อ่านรายละเอียดและวิธีแก้ปัญหาได้ที่คู่มือทางการของ Microsoft: learn.microsoft.com/en-us/windows/wsl/install

1.2 ตรวจสอบว่าเป็น WSL2

wsl -l -v

คอลัมน์ VERSION ต้องเป็น 2 (ถ้าติดตั้งไม่ผ่าน มักเกิดจากยังไม่เปิด Virtualization ใน BIOS/UEFI)

1.3 Windows Terminal

Windows 11 มีติดมาให้แล้ว ส่วน Windows 10 ติดตั้งได้จาก Microsoft Store — แนะนำตั้งโปรไฟล์ Ubuntu เป็นค่าเริ่มต้น

กติกาสำคัญ: ตั้งแต่จุดนี้เป็นต้นไป คำสั่งเทอร์มินัลทั้งหมดในเอกสารนี้ให้รันใน Ubuntu (WSL) ไม่ใช่ PowerShell — ยกเว้นหัวข้อที่ระบุว่าเป็นแอปฝั่ง Windows

1.4 อัปเดตแพ็กเกจ และติดตั้ง Homebrew

sudo apt update && sudo apt upgrade -y
sudo apt install -y build-essential curl git

ติดตั้ง Homebrew (ใช้บน Linux/WSL ได้ จะใช้ติดตั้ง rtk และเครื่องมืออื่น):

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

ติดตั้งเสร็จ อย่าลืมรันคำสั่งในส่วน Next steps ที่ตัวติดตั้งแสดง เพื่อเพิ่ม brew เข้า PATH แล้วตรวจสอบด้วย brew --version

macOS

1.1 ตรวจชิปของเครื่อง: Apple Silicon หรือ Intel

เมนู Apple → About This Mac — ถ้าเห็น Chip: Apple M1/M2/M3/M4 คือ Apple Silicon ถ้าเห็น Processor: Intel คือเครื่อง Intel ทั้งสองแบบใช้ทำ workshop ได้ แต่มีจุดต่างที่ควรรู้:

  • Homebrew ติดตั้งคนละตำแหน่ง — Apple Silicon อยู่ที่ /opt/homebrew ส่วน Intel อยู่ที่ /usr/local ไม่ต้องจำ path เอง แค่รันคำสั่งในส่วน Next steps ที่ตัวติดตั้งแสดงให้ครบ
  • Apple Silicon — เครื่องมือทั้งหมดใน workshop นี้มีเวอร์ชัน Apple Silicon แล้ว ปกติไม่ต้องทำอะไรเพิ่ม แต่ถ้าบังเอิญเจอโปรแกรมเก่าที่มีแต่เวอร์ชัน Intel ระบบจะชวนติดตั้ง Rosetta 2 ให้เอง (หรือรัน softwareupdate --install-rosetta --agree-to-license)
  • Intel Mac — เป็นเครื่องรุ่นปี 2020 ลงไป ให้อัปเดต macOS เป็นเวอร์ชันใหม่ที่สุดที่เครื่องรองรับก่อน (Homebrew ซัพพอร์ตเฉพาะ macOS 3 เวอร์ชันล่าสุด) และถ้า RAM 8 GB อาจหน่วงเมื่อเปิด IDE กับ AI agent พร้อมกัน — ปิดแอปที่ไม่ใช้ระหว่าง workshop จะช่วยได้

1.2 ติดตั้ง Xcode Command Line Tools

เปิดแอป Terminal แล้วรัน (ได้ Git และคอมไพเลอร์พื้นฐานมาด้วย):

xcode-select --install

1.3 ติดตั้ง Homebrew

Homebrew คือ package manager หลักที่เราจะใช้ติดตั้งเครื่องมือเกือบทั้งหมด:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

ติดตั้งเสร็จ รันคำสั่งในส่วน Next steps ที่ตัวติดตั้งแสดง เพื่อเพิ่ม brew เข้า PATH แล้วตรวจสอบด้วย brew --version

02

พื้นฐานคำสั่ง Linux ใน WSL

ขั้นตอนถัดจากนี้ทำผ่านเทอร์มินัลเกือบทั้งหมด ถ้าเพิ่งใช้ Linux ครั้งแรก ทำความรู้จักคำสั่งชุดนี้ก่อนสัก 10 นาที (ผู้ใช้ macOS ใช้คำสั่งชุดเดียวกันนี้ในแอป Terminal ได้เลย)

2.1 โครงสร้างพื้นฐาน: บ้านของคุณคือ ~

ใน Linux เส้นทางไฟล์ (path) คั่นด้วย / ไม่ใช่ \ แบบ Windows และตัวพิมพ์เล็ก–ใหญ่ถือเป็นคนละชื่อกัน โฟลเดอร์ประจำตัวของคุณ (home) คือ /home/ชื่อผู้ใช้ เขียนย่อว่า ~ — พิมพ์ cd ~ เมื่อไรก็กลับบ้านทันที และให้เก็บโปรเจกต์ทั้งหมดของ workshop ไว้ใต้ ~ เสมอ

2.2 คำสั่งที่ใช้บ่อย

คำสั่งใช้ทำอะไรตัวอย่าง
pwdดูว่าตอนนี้อยู่โฟลเดอร์ไหนpwd
ls, ls -laดูรายชื่อไฟล์ (-la = รวมไฟล์ซ่อน + รายละเอียด)ls -la
cdย้ายไปโฟลเดอร์อื่น (cd .. = ถอยขึ้นหนึ่งชั้น)cd ~/projects
mkdir -pสร้างโฟลเดอร์ (ซ้อนกันหลายชั้นได้)mkdir -p ~/projects/workshop
cp, cp -rคัดลอกไฟล์ (-r = ทั้งโฟลเดอร์)cp -r src backup
mvย้ายไฟล์ หรือเปลี่ยนชื่อmv old.txt new.txt
rm, rm -rfลบไฟล์ (-rf = ทั้งโฟลเดอร์)rm -rf node_modules
catแสดงเนื้อหาไฟล์cat README.md
nanoแก้ไฟล์ในเทอร์มินัล (Ctrl+O บันทึก, Ctrl+X ออก)nano ~/.bashrc
whichเช็กว่าคำสั่งติดตั้งอยู่ที่ไหนwhich node
sudoรันคำสั่งด้วยสิทธิ์ผู้ดูแล (ใช้รหัสผ่าน Linux ที่ตั้งไว้)sudo apt update
clearล้างหน้าจอclear
ระวัง: rm ลบถาวรทันที ไม่มีถังขยะให้กู้คืน — ก่อนกด Enter กับ rm -rf ให้อ่าน path ซ้ำอีกครั้งเสมอ

เทคนิคช่วยชีวิต:

  • กด Tab เพื่อเติมชื่อไฟล์/คำสั่งอัตโนมัติ (กดสองครั้งเพื่อดูตัวเลือกทั้งหมด)
  • ลูกศรขึ้น/ลง เรียกคำสั่งที่เคยพิมพ์กลับมา (history = ดูทั้งหมด)
  • Ctrl+C ยกเลิกคำสั่งที่กำลังค้างอยู่
  • วาง (paste) ใน Windows Terminal ใช้คลิกขวา หรือ Ctrl+Shift+V

2.3 ไป–กลับระหว่าง WSL กับไดรฟ์ของ Windows

ไดรฟ์ทุกตัวของ Windows ถูก mount ไว้ใต้ /mnt/ ตามตัวอักษรไดรฟ์ (ตัวพิมพ์เล็ก): C: → /mnt/c, D: → /mnt/d

cd /mnt/c/Users/<ชื่อผู้ใช้ Windows>/Downloads   # เข้าโฟลเดอร์ Downloads ของ Windows
cd /mnt/d                                       # เข้าไดรฟ์ D:
wslpath 'C:\Users\me\Desktop'                   # แปลง path แบบ Windows เป็นแบบ Linux

สลับมุมมองกับฝั่ง Windows ได้สองทาง:

  • จาก WSL เปิดโฟลเดอร์ปัจจุบันด้วยแอป Windows: explorer.exe . (File Explorer) หรือ code . (VS Code)
  • จาก Windows เข้าไฟล์ใน Ubuntu ผ่านหัวข้อ Linux ใน File Explorer หรือพิมพ์ \\wsl$ ใน address bar
งานทั้งหมดของ workshop ให้ทำในโฮมฝั่ง Linux (~) — เข้า /mnt/c เฉพาะตอนต้องหยิบไฟล์จากฝั่ง Windows เพราะทำงานช้ากว่ามากและ symlink มีปัญหา

2.3 ไดรฟ์และโฟลเดอร์บน macOS

โฟลเดอร์ผู้ใช้ของคุณคือ /Users/ชื่อผู้ใช้ (ก็คือ ~ เช่นกัน) ส่วนไดรฟ์ภายนอก/USB จะอยู่ที่ /Volumes/ชื่อดิสก์ — เปิดโฟลเดอร์ปัจจุบันใน Finder ได้ด้วย open . และเปิดใน VS Code ด้วย code .

2.4 ลองฝึกจริงหนึ่งรอบ

cd ~
mkdir -p ~/projects/workshop
cd ~/projects/workshop
touch hello.txt
ls -la
pwd

ถ้าบรรทัดสุดท้ายแสดง /home/ชื่อผู้ใช้/projects/workshop (หรือ /Users/... บน macOS) แปลว่าคุณพร้อมใช้เทอร์มินัลแล้ว

03

ติดตั้งเครื่องมือพื้นฐาน

3.1 Git CLI จำเป็น

Windows · รันใน WSL — ส่วนใหญ่ Ubuntu ติด Git มาให้แล้ว (เราติดตั้งซ้ำไปในขั้น 1.4 แล้วด้วย) ตรวจสอบด้วย git --version

macOS — Git มากับ Xcode Command Line Tools แล้ว ตรวจสอบด้วย git --version

ตั้งค่าชื่อและอีเมล (ใช้อีเมลเดียวกับบัญชี GitHub):

git config --global user.name "ชื่อของคุณ"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

3.2 Node.js LTS ผ่าน nvm จำเป็น

CLI สาย AI หลายตัวติดตั้งผ่าน npm จึงต้องมี Node.js ก่อน แนะนำติดตั้งผ่าน nvm เพื่อสลับเวอร์ชันได้ง่าย:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

ปิด–เปิดเทอร์มินัลใหม่ แล้วติดตั้ง Node LTS:

nvm install --lts
node -v && npm -v

3.3 GitHub CLI (gh) จำเป็น

brew install gh

ยังไม่ต้องล็อกอิน — เดี๋ยวทำหลังสมัครบัญชี GitHub ในขั้นตอนที่ 05

3.4 VS Code จำเป็น

ดาวน์โหลดจาก code.visualstudio.com (ติดตั้งเป็นแอปปกติฝั่ง Windows/macOS)

Windows — ติดตั้ง extension WSL (ms-vscode-remote.remote-wsl) ด้วย เพื่อให้เปิดโปรเจกต์ที่อยู่ใน Ubuntu ได้โดยพิมพ์ code . จากในเทอร์มินัล WSL

3.5 GitHub Desktop ทางเลือก

สำหรับคนที่ถนัดจัดการ Git ผ่านหน้าจอ GUI ดาวน์โหลดจาก desktop.github.com (แอปฝั่ง Windows/macOS)

สมัครบัญชีแพลตฟอร์มนักพัฒนา

สมัคร GitHub ก่อน เพราะอีกสองบริการจะล็อกอินต่อด้วยบัญชี GitHub

  1. GitHub — github.com/signup สมัครแล้วเปิด 2FA (Settings → Password and authentication)

gh auth login

เลือก GitHub.com → HTTPS → Login with a web browser แล้วทำตามขั้นตอน ตรวจสอบผลด้วย gh auth status

ติดตั้ง AI Coding CLI และแอป

Windows — CLI ทุกตัวในหัวข้อนี้ติดตั้งใน Ubuntu (WSL) ส่วนแอป (Cursor / Antigravity IDE / ZCode) ติดตั้งฝั่ง Windows ปกติ

6.1 Antigravity CLI จำเป็น · ฟรี

curl -fsSL https://antigravity.google/cli/install.sh | bash

ได้คำสั่งชื่อ agy — รันแล้วล็อกอินด้วยบัญชี Google ใช้ฟรี — เอกสาร: antigravity.google/docs/cli

Antigravity CLI คือตัวแทนของ Gemini CLI เดิม — Google เปลี่ยนชื่อ/แพลตฟอร์มเมื่อ พ.ค. 2026 และ Gemini CLI หยุดให้บริการผู้ใช้ทั่วไปแล้วตั้งแต่ มิ.ย. 2026 ถ้าเจอบทเรียนเก่าที่อ้างถึง Gemini CLI ให้ใช้ Antigravity CLI แทนได้เลย

6.2 OpenCode จำเป็น · ฟรี

curl -fsSL https://opencode.ai/install | bash

(หรือ npm install -g opencode-ai) แล้วรัน opencode auth login เชื่อม provider ที่มี — สาย Free จับคู่กับ Google หรือ GLM trial ได้เลย

6.3 rtk CLI — Token Optimization จำเป็น

rtk เป็น CLI proxy ที่ช่วยลดการใช้ token ของ AI agent ลง 60–90% เวลาเรียกคำสั่ง dev ทั่วไป (git, test, build ฯลฯ):

brew install rtk
rtk --version
rtk gain

rtk gain ใช้ดูสถิติ token ที่ประหยัดได้ — ถ้าคำสั่งขึ้น error แสดงว่าเครื่องมี rtk คนละตัว (Rust Type Kit) ให้ตรวจสอบด้วย which rtk

6.4 Claude Code ทางเลือก — ต้องมี Claude Pro

curl -fsSL https://claude.ai/install.sh | bash

(หรือ npm install -g @anthropic-ai/claude-code) รัน claude แล้วล็อกอินด้วยบัญชี Claude Pro/Max — ติดตั้งเฉพาะคนที่สมัครแผนเสียเงินไว้

6.5 Codex CLI ทางเลือก — ต้องมี ChatGPT Plus

npm install -g @openai/codex

รัน codex แล้วเลือก Sign in with ChatGPT — เอกสาร: developers.openai.com/codex/cli

6.6 แอปเดสก์ท็อป

  • Antigravity IDE (ฟรี) — ดาวน์โหลดจาก antigravity.google/download ล็อกอินด้วยบัญชี Google เดียวกับ CLI
  • Cursor (ฟรี) — ดาวน์โหลดจาก cursor.com แล้วล็อกอินด้วยบัญชีที่สมัครไว้
  • ZCode ทางเลือก — ดาวน์โหลดจาก zcode.z.ai แล้วเชื่อมกับ GLM Coding Plan (ดูวิธีที่ Connect Models & Plans)
  • OpenDesign ทางเลือก — ติดตั้งจาก open-design.ai ตอนเปิดครั้งแรกเลือก local coding agent แล้วชี้ไปที่ CLI ที่ติดตั้งไว้ (เช่น OpenCode)
07

ติดตั้ง Skills

Skill คือชุดคำสั่ง+ความรู้ในรูปไฟล์ SKILL.md ที่สอนให้ agent ทำงานเฉพาะทางได้ดีขึ้น เป็นมาตรฐานเปิดที่ใช้ได้ทั้ง Claude Code, Codex, OpenCode และ Cursor

7.1 Superpowers จำเป็น

ชุด skill ยอดนิยมด้านกระบวนการพัฒนา (brainstorming, TDD, systematic debugging ฯลฯ) จาก github.com/obra/superpowers — ติดตั้งโดยเปิด Claude Code แล้วพิมพ์:

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

ถ้าไม่ได้ใช้ Claude Code: clone obra/superpowers แล้ว copy โฟลเดอร์ skill ที่ต้องการเข้า ~/.claude/skills แบบเดียวกับข้อ 7.2 ได้เช่นกัน

7.2 Skills ทางการจาก Anthropic ทางเลือก

คลังตัวอย่าง skill ของ Anthropic (งานเอกสาร docx/pdf/pptx/xlsx, สร้าง artifact ฯลฯ) อยู่ที่ github.com/anthropics/skills วิธีติดตั้งแบบ manual ที่ใช้ได้กับทุกแพลตฟอร์ม:

mkdir -p ~/.claude/skills
git clone https://github.com/anthropics/skills.git /tmp/anthropic-skills
cp -r /tmp/anthropic-skills/<ชื่อโฟลเดอร์สกิลที่ต้องการ> ~/.claude/skills/

7.3 หา skill เพิ่มเติม

  • ใน Claude Code พิมพ์ /plugin แล้วเข้าแท็บ Discover
  • แคตตาล็อกทางการ: claude.com/plugins
08

แชร์ Skills ข้ามแพลตฟอร์มด้วย Symlink

แทนที่จะ copy skill ซ้ำไว้หลายที่ ให้เก็บไว้ที่เดียวคือ ~/.claude/skills เป็น source of truth แล้วให้แพลตฟอร์มอื่นชี้มาที่นี่ — อัปเดตครั้งเดียว ใช้ได้ทุกเครื่องมือ

  • OpenCode — ไม่ต้องทำอะไร อ่าน ~/.claude/skills ให้อัตโนมัติอยู่แล้ว (เอกสาร)
  • Codex — อ่านจาก ~/.codex/skills (เอกสาร) ให้ symlink รายสกิลดังนี้:
mkdir -p ~/.codex/skills
for s in ~/.claude/skills/*/; do
  ln -sfn "$s" ~/.codex/skills/"$(basename "$s")"
done
ls -la ~/.codex/skills

เพิ่ม skill ใหม่ใน ~/.claude/skills เมื่อไร ก็รันลูปนี้ซ้ำหนึ่งครั้งเพื่ออัปเดตลิงก์ (ln -sfn เขียนทับลิงก์เดิมให้เอง)

Windows — ทำทั้งหมดนี้ใน WSL และเก็บไฟล์ไว้ในโฮมของ Linux (~/) อย่าเก็บใน /mnt/c/... เพราะ symlink และ performance จะมีปัญหา
09

เชื่อมต่อ Vercel เข้ากับเครื่องมือแต่ละตัว

9.1 Vercel CLI จำเป็น

npm install -g vercel
vercel login
vercel whoami

9.2 Vercel Plugin สำหรับ Claude Code ทางเลือก — สำหรับผู้ใช้ Claude Code

ติดตั้งปลั๊กอินทางการของ Vercel (ได้คำสั่ง /deploy, ดู log, จัดการ env และ skill เกี่ยวกับ Next.js/AI SDK อีกชุดใหญ่) — เปิด Claude Code แล้วพิมพ์:

/plugin install vercel@claude-plugins-official

9.3 Vercel MCP สำหรับแพลตฟอร์มอื่น

Vercel มี MCP server ที่ endpoint https://mcp.vercel.com ใช้เชื่อมกับเครื่องมือแต่ละตัว (ครั้งแรกจะมีหน้า OAuth ให้ล็อกอิน Vercel):

เครื่องมือวิธีเชื่อมต่อ
Claude Codeรัน claude mcp add --transport http vercel https://mcp.vercel.com
CursorSettings → MCP → Add server แล้วใส่ URL (หรือกดปุ่ม Add to Cursor ในหน้าเอกสาร Vercel)
ChatGPTSettings → Connectors → เพิ่ม MCP connector ด้วย URL เดียวกัน
Antigravity CLIเพิ่ม MCP server ด้วย URL เดียวกัน — ดูวิธีของเวอร์ชันที่ใช้ใน antigravity.google/docs/cli
OpenCodeเพิ่มใน opencode.json: {"mcp":{"vercel":{"type":"remote","url":"https://mcp.vercel.com"}}}

รายละเอียดของแต่ละ client ดูได้ที่ vercel.com/docs/mcp

Supabase ก็มี MCP server เช่นกัน — ถ้าอยากเตรียมล่วงหน้า ดูที่ supabase.com/docs/guides/getting-started/mcp
